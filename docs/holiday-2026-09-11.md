# Holiday pipeline — 2026-09-11

Unattended for 2-3 days. Clone the blind planning oracle into the v21 champion's policy
network, correct the clone with two DAgger rounds, benchmark each clone on held-out seeds,
then hand the best one to ordinary PPO. WORKLOG.md (2026-09-11, second entry) has the
reasoning; this is the runbook.

## What is running

`asteroids-holiday.service` (transient, `cloud/asteroids-holiday.sh`) runs
`scripts/holiday_pipeline.py run`, logging to `experiments/holiday-2026-09-11/pipeline.log`.
`asteroids.service` (v21) is stopped for the duration. Steps and budgets:

| step | what | budget | output |
|---|---|---|---|
| source | snapshot of the v21 champion (ep 134,500) | – | `source/` |
| r0 | oracle drives, oracle labels; round 29, seeds 5,000,000+ | 10h | `r0.npz`, `r0.json` |
| c0 | clone of source on r0; benchmark | ~1h | `c0/`, `c0-bench.json`, `c0-retention.json` |
| r1 | **c0 drives**, oracle labels (DAgger); seeds 6,000,000+ | 5h | `r1.npz` |
| c1 | clone on r0+r1; benchmark | ~1h | `c1/` … |
| r2 | c1 drives; seeds 7,000,000+ | 5h | `r2.npz` |
| c2 | clone on r0+r1+r2; benchmark | ~1h | `c2/` … |
| decide | best `current` clear ≥ 0.40 → fine-tune, else resume v21 | – | `decision.json` |

If the clone wins: `models/oracle-survival-v3-v22-oracle-clone/` is created with the clone
primed as its protected champion at its measured score, `asteroids-v22-clone.conf` is
installed as the `asteroids.service` drop-in, and the service starts (LR 1.67e-5, ent 0.0025,
KL 0.02, `START_STAGE=29`, seed 2209). If it loses, or anything crashes, the service starts
with the v21 drop-in still installed and v21 resumes from its newest checkpoint.

`asteroids-holiday-watchdog.timer` runs hourly and starts `asteroids.service` if neither it
nor the pipeline is active.

## Reading it

```bash
ssh oracle
cd ~/Asteroids
tail -f experiments/holiday-2026-09-11/pipeline.log       # step by step
cat experiments/holiday-2026-09-11/scores.json              # clone benchmarks so far
cat experiments/holiday-2026-09-11/decision.json            # once decided
cat experiments/holiday-2026-09-11/c0/clone-report.json     # agreement numbers
systemctl status asteroids-holiday asteroids                # which one is alive
./run.sh status models/oracle-survival-v3-v22-oracle-clone  # once fine-tuning
```

Numbers that matter, in order:
- `c*-bench.json` → `current.clear_rate` on 256 seeds. The v21 source scores 0.672 on the same
  seeds; the blind oracle 0.922 on other seeds. This is the only judge of a clone.
- `clone-report.json` → `final_agreement_val.top1` against `majority_baseline_val`, and
  `in_safe_set`. Agreement at the majority baseline means the oracle's choice is not a
  function of the observation (the 2026-08-26 reading); agreement well above it with a poor
  clear that r1/r2 repair means distribution shift, which is what DAgger is for.
- Retention (`c*-retention.json`): completion per round 23-28; the fine-tune's recovery
  machinery handles slippage, but a clone that has forgotten round 23 is a warning.
- Once fine-tuning: `evaluation.jsonl` in 20k-episode buckets, never one pooled reading.

## Stopping or rolling back

```bash
sudo systemctl stop asteroids-holiday          # pipeline's own fallback starts asteroids
sudo systemctl disable --now asteroids-holiday-watchdog.timer
# to force v21 back after the clone was installed:
sudo install -m 644 experiments/holiday-2026-09-11/previous-bridge.conf \
     /etc/systemd/system/asteroids.service.d/bridge.conf
sudo systemctl daemon-reload && sudo systemctl restart asteroids
```

Re-running `cloud/asteroids-holiday.sh` resumes: every step whose output exists is skipped.
